# Зафиксированные решения по рейдам

## Назначение

Документ отделяет закрытые решения от технических деталей реализации. Codex не
должен повторно предлагать альтернативы из этого списка, если новый факт не
создаёт прямого конфликта с текущим проектом ТЗ.

Детальные значения ключей, sorting и acceptance criteria определяет
`requirements.md`. Этот файл фиксирует причины и границы решений, но не
переопределяет нормативный контракт.

## Продуктовые решения

| Область | Решение |
|---|---|
| Единица отображения | Одна строка на игровой аккаунт за рейдовый уикенд |
| Видимые данные атак | Только агрегат; районные и поатаковые листы не создаются |
| Участники | Только `members` выбранного сезона CoC API |
| Игрок без атак вне `members` | Не показывается |
| Обычный район | Норма две атаки на 100% разрушения |
| Столица | Норма три атаки на 100% разрушения |
| Нормо-очки обычной атаки | `destructionPercent × 2 / 100` |
| Нормо-очки атаки Столицы | `destructionPercent × 3 / 100` |
| Коэффициент | `normal_points / 6` |
| Идеальный ориентир | Шесть нормативных атак дают `K = 1,00` |
| Добивки | Каждый получает вклад своей атаки; специальной компенсации нет |
| Атаки | Всегда показываются как `x/6` |
| Бонусная атака | Игрок без неё всё равно нарушает требование `6/6` |
| Подсветка ongoing | Отсутствует |
| Подсветка ended | При `< 6` красится только ячейка `Атаки` |
| Другие статусные цвета | Не используются |
| Сортировка | Коэффициент по убыванию |
| Место `№` | Позиция игрока после сортировки |
| Средний коэффициент | На этом этапе отсутствует |
| Золото столицы | Справочная колонка, в формулу не входит |

## Дефолтные колонки

Физически первой остаётся скрытая service-колонка `__bot_key`.

Нормативный список видимых системных колонок и стабильных `column_key`
находится в разделе 10.2 `requirements.md`. Выбран подробный namespace:
`player_tag`, `player_name`, `capital_resources_looted`. `normal_points` и
`coefficient` передаются в Google Sheets числами. Первый отображается форматом
`0.00`, второй — целым процентом `0%`; золото отображается форматом `#,##0`.

## Пользовательские колонки

- Связь с `Составом` повторяет фактическое поведение CWL.
- Совпадение определяется по нормализованному видимому заголовку без учёта
  регистра.
- Значение состава используется только для пустой рейдовой ячейки.
- Непустое ручное значение в `Рейдах` имеет приоритет.
- Ручные значения импортируются только из зарегистрированных managed blocks.
- Строки связываются через стабильный `__bot_key`, а не nickname или номер.

## Жизненный цикл листов

- Канонический активный лист называется `Рейды`.
- Между событиями он продолжает показывать последний завершённый уикенд.
- При новом уикенде старый active архивируется через staging-ротацию.
- Архив называется `Рейды YYYY-MM-DD`, дата берётся из UTC `startTime`.
- При конфликте имени применяется безопасный суффикс ` - N`.
- Одновременно хранится не более четырёх зарегистрированных архивных листов.
- Active `Рейды` в лимит не входит.
- При появлении пятого архива удаляется самый старый bot-owned архив.
- Удаляется только Google-вкладка и связанная metadata; агрегированный SQLite
  state сезона сохраняется.
- Лист с похожим именем без bot registry автоматически не удаляется.

## Пропущенные события

- Промежуточные уикенды, которые никогда не были active-сезоном бота, не
  восстанавливаются.
- При обнаружении нового сезона старый известный active-сезон финализируется из
  API, если ещё доступен в окне последних сезонов.
- Если финальный ответ исчез из API, архивируется последнее сохранённое
  состояние и формируется предупреждение.
- Значение `RAID_SEASON_FETCH_LIMIT=5` предназначено для поиска старого
  active-сезона, а не для backfill.

## Архитектурные решения

- CoC API владеет текущими техническими рейдовыми данными.
- Google Sheets владеет ручными значениями рейдовых user-колонок.
- SQLite владеет runtime binding, registry архивов и хранит snapshots строк.
- Внутренний расчёт выполняется через целые `weighted_damage_units`.
- `Capital Peak` определяется по подтверждённому `district.id = 70000000`.
- Ended mismatch между `members[].attacks` и attack log является strict
  contract error; ongoing mismatch является retryable domain error до write.
- Все три домена — composition, CWL и raids — готовятся до первой записи.
- Google Sheets и SQLite не образуют общей транзакции.
- Ошибка pruning после успешной ротации не должна откатывать созданный active
  лист. Sync сохраняет status `success`, report получает специальный cleanup
  warning без общего partial-write текста, а registry сохраняется, чтобы
  pruning повторился при следующем запуске.
- `_bot_state` остаётся служебным зеркалом; SQLite binding имеет приоритет.
- `SSOT.md` не описывает рейды до их реализации и обновляется коммитом 8.

## Не входит в задачу

- Назначение районов игрокам.
- Поиск «брошенного» района.
- Определение кражи добивки.
- Награды или штрафы за последний удар.
- Нулевые строки игроков из текущего состава.
- Скользящий рейтинг или средний коэффициент.
- Автоматические сообщения и наказания игрокам.
- Планировщик фоновой синхронизации.
- Изменение доменных правил состава и CWL.
