# Зафиксированные решения

Этот файл не создаёт новые требования, а фиксирует уже согласованные ответы.
Codex не должен повторно выбирать перечисленные варианты.

## Продукт

| Вопрос | Решение |
|---|---|
| Название основной команды | `/cwl_forecast` |
| Кто запускает прогноз | Любой участник подключённой группы |
| Какие кланы проверяются | Все активные привязанные к chat кланы в `sort_order` |
| Количество будущих соперников | Все оставшиеся раунды |
| Текущая война | `inWar`, иначе ближайшая `preparation` |
| Размер прогнозного состава | `teamSize` выбранной войны |
| Неполный зарегистрированный состав | Дополнять `—` |
| Последняя война | Только наш и текущий составы |
| Ошибка одного клана | Успешные прогнозы + одна краткая сводка ошибок |
| Ширина | Всегда одно сообщение на клан |
| Заголовок колонок | Два пробела, без вертикальных черт |
| Строки матрицы | Только `|`, без пробелов |
| Порядок всех составов | TH DESC, затем нормализованный player tag ASC |
| Итоговая строка | Суммы TH по колонкам, между значениями два пробела |
| Cooldown | Отдельные 60 секунд, с момента принятия команды |
| Параллельный запуск | `Прогноз ЛВК уже формируется` |

## Будущее расписание

| Вопрос | Решение |
|---|---|
| Можно ли вычислять из порядка `clans` | Нет, гарантия API отсутствует |
| OCR скриншотов | Полностью исключён |
| Способ ввода | Отдельная кнопочная команда `/cwl_forecast_schedule` |
| Кто вводит | Только creator/admin текущей группы |
| Информация на кнопке | Имя, уровень клана и тег |
| Расположение кнопок | Один клан на строку |
| Повторное использование | На весь season + League Group + наш clan |
| Совместное использование | Глобально между Telegram chats |
| Что хранить | Теги и номера раундов, не display names/levels |
| API-известные раунды | Автозаполнение, редактирование запрещено |
| Несовпадение с будущим реальным API | Блокировать прогноз, просить админа исправить |
| Нет полного расписания | Не отправлять частичный прогноз; просить админа |
| TTL кнопочной сессии | 10 минут, configurable |

## Emoji

| Вопрос | Решение |
|---|---|
| Имя JSON | Уже существующий `resources/telegram_emoji_catalog.json` |
| Дублировать/перемещать файл | Нет |
| Передача Telegram | Message entities `custom_emoji` |
| Offset | UTF-16 code units |
| Текст с entities | Значение `fallback` |
| Plain fallback | Значение `fallback_text` |
| Когда retry plain text | Только HTTP 400 custom-emoji отправки, один раз |
| Keycap-цифры | Стандартные Unicode emoji, без custom entity |

## Разработка и релиз

| Вопрос | Решение |
|---|---|
| Ветка | `feat/cwl-forecast-v1.1.0` от актуального `main` |
| Режим работы | По одному тематическому этапу |
| Commit | После каждого зелёного этапа автоматически разрешён |
| Нужен вопрос между этапами | Нет, если нет блокера или нового решения |
| Финальная версия | `1.1.0` |
| Push/PR/tag/release/deploy | Не разрешены этим заданием |

## Обоснование ручного расписания

В проверенной обезличенной fixture и в реальном неанонимном ответе будущие
раунды содержат только `"#0"`. Ручка войны не может быть вызвана до появления
реального `warTag`. В игровом UI расписание видно, однако публичный API не
документирует поле или стабильный алгоритм его восстановления. Ответы
разработчиков сообщества также не подтвердили закономерность. Поэтому ручной
выбор по актуальному списку API-кланов является единственным способом не
выдавать догадку за гарантированное расписание.
