## Назначение пакета

Архив распаковывается непосредственно в:

```text
clash-sheet-sync-bot/docs/tasks/cwl_forecast/
```

После распаковки Codex должен ознакомиться со всем репозиторием и этими
документами, создать от актуального `main` ветку
`feat/cwl-forecast-v1.1.0`, выполнить работу по этапам и создать отдельный
тематический commit после каждого успешно проверенного этапа.

Разрешение пользователя распространяется на создание ветки и commits по
`commit-plan.md`. Оно не распространяется на push, Pull Request, tag,
GitHub Release, deploy и применение миграции к production-базе.

## Документы

1. `requirements.md` — нормативное ТЗ и критерии приёмки.
2. `decisions.md` — уже принятые решения, которые нельзя выбирать заново.
3. `architecture.md` — рекомендуемая архитектура и владение данными.
4. `commit-plan.md` — этапы реализации и границы каждого commit.
5. `verification.md` — автоматические и ручные проверки.
6. `codex.md` — обязательный рабочий протокол Codex.

При конфликте приоритет следующий:

1. актуальные прямые указания пользователя;
2. `requirements.md`;
3. `decisions.md`;
4. фактические контракты текущего кода и `SSOT.md`;
5. остальные документы этого каталога.

Не предусмотренное ТЗ противоречие нельзя разрешать молча. Codex должен
остановиться, привести факты и запросить решение.

## Важное ограничение API

Официальный League Group API возвращает `"#0"` вместо `warTag` для ещё не
созданных будущих войн. Порядок будущих соперников нельзя надёжно вывести из
порядка массива `clans`. Поэтому задача не использует алгоритмическое
предсказание и OCR: администратор один раз вводит расписание через отдельную
кнопочную команду, после чего оно переиспользуется для той же ЛВК.

## Начало работы

Codex выполняет `codex.md` без дополнительных подтверждений между этапами,
если проверки зелёные и не возникло материального противоречия. Первый commit
фиксирует только распакованные task-docs:

```text
docs: add CWL forecast implementation task
```

Последний commit подготавливает релиз `1.1.0`, но не публикует его.
